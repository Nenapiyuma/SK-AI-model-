# SK AI 1.3T Architecture

## Verified status

The uploaded project was inspected before this architecture was added. The existing presets are not 1.3 trillion parameters. Independent counting from the configured tensor shapes gives approximately 1.31M, 1.213B, 6.195B and 56.863B parameters.

The existing tensor backend also uses float32 arrays and cannot instantiate a 1.3T model on the development environment. Therefore the repository must distinguish an architecture specification from a generated checkpoint.

## Exact 1.3T configuration

- Total parameters: 1,300,000,000,000 exactly
- Layers: 59
- Hidden size: 16,384
- Attention: 128 query heads, 8 KV heads
- Head dimension: 128
- SwiGLU intermediate size: 54,490 per expert
- MoE: 8 experts per layer, top-2 active experts per token
- Vocabulary: 133,120
- Tied input/output embeddings
- Trainable output bias: 133,120 parameters
- Context: 131,072 tokens
- Training/checkpoint precision: BF16
- Inference target: INT4 block-128 with FP16 scales

The output bias is a normal trainable model parameter and is included in the parameter equation. It is not padding or a storage trick.

## Genuine storage accounting

For 1.3T parameters:

| Format | Raw weight bytes | Decimal TB | TiB |
|---|---:|---:|---:|
| FP32 | 2,600,000,000,000 | 2.600 | 2.365 |
| BF16/FP16 | 2,600,000,000,000 | 2.600 | 2.365 |
| INT8 | 1,300,000,000,000 | 1.300 | 1.182 |
| INT4 | 650,000,000,000 | 0.650 | 0.591 |

With INT4 block size 128 and one FP16 scale per block, the estimated payload is 670,312,500,000 bytes, about 0.670 TB or 0.610 TiB. Tensor indexes, metadata and special tensors add a small amount.

A roughly 1 TB artifact target is therefore compatible with genuine 1.3T parameters without padding.

## Training memory

A rough lower-bound state estimate for BF16 parameters plus BF16 gradients and FP32 Adam moments is:

- parameters: 2.6 TB
- gradients: 2.6 TB
- Adam first moment: 5.2 TB
- Adam second moment: 5.2 TB
- subtotal: 15.6 TB decimal

This excludes activations, communication buffers, framework overhead and fragmentation. Single-machine training is not realistic.

## Distributed training target

Production training should use FSDP or ZeRO-3 for parameter/gradient/optimizer sharding, expert parallelism for MoE layers, tensor parallelism for large projections, pipeline parallelism where cluster topology requires it, BF16 mixed precision, activation checkpointing and resumable sharded checkpoints.

A final cluster size must be chosen from measured throughput and memory headroom. The project does not claim that training has happened merely because this configuration exists.

## Storage architecture

GitHub is for source, tests, configs and CI. The 1.3T checkpoint must never be committed to Git.

The release path should publish immutable checkpoint shards plus a manifest and SHA-256 checksums, while storing the large shards in object storage or a model registry designed for TB-scale artifacts.

## Validation gates

The exact architecture audit must pass before a checkpoint can be labeled SK AI 1.3T.

A real checkpoint must additionally pass tensor-shape validation, actual tensor parameter summation, shard/index validation, SHA-256 validation, tokenizer tests, forward-pass smoke testing, distributed initialization testing and quantization reconstruction/error measurement.
